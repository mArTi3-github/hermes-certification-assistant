# Порядок документа в .docx

`python-docx` отдаёт `Document.paragraphs` и `Document.tables` двумя независимыми списками,
поэтому читатель, пользующийся только ими, теряет позицию каждой таблицы относительно
заголовков и текста вокруг. Там, где таблица принадлежит заголовку над ней («Проверяемые
требования» → таблица, блок теста `4.1.N`), порядок — это информация, которую из двух списков
не восстановить.

## Когда применять

- разбор чужого отчёта `.docx` по разделам: текст, таблицы и их взаимное расположение нужны
  вместе;
- проверка, что таблица попала в нужный раздел, а не «где-то в документе»;
- нужен срез одного раздела (`--start/--end`) для перечитывания после правки.

Остальные операции с `.docx` — штатный скилл `microsoft-office` (`docx_read.py --structure/--text`,
`docx_create.py`, `docx_edit.py`, `docx_comments.py`, `docx_validate.py`, `references/word.md`).
Своей копии `docx` в профиле нет намеренно: она отвязывает скилл от обновлений Hermes.

## Инструмент

```bash
S=<каталог этого скилла>
PY=<интерпретатор с python-docx>
"$PY" "$S/scripts/docx_read_ordered.py" file.docx > dump.txt                       # текст по порядку
"$PY" "$S/scripts/docx_read_ordered.py" file.docx --json                            # блоки как JSON
"$PY" "$S/scripts/docx_read_ordered.py" file.docx --start "4.1.1" --end "4.1.2"     # один раздел
```

Флаги: `--json` (блоки как JSON), `--empty` (сохранять пустые абзацы), `--no-headers`
(без колонтитулов), `--start/--end` (границы раздела по тексту заголовка).

На каждый блок печатается вид (`P<n>` — абзац, `T<n>` — таблица), имя стиля и текст; строки
таблицы идут с разделителем `|`. Дамп сохраняют в файл: заключение ссылается на раздел, абзац и
рисунок, а не на пересказ.

## Грабли

- **Интерпретатор.** Скрипт падает на `from docx import Document`, если запускать его
  `python3` без `python-docx`: `pip` и `python3` могут смотреть в разные Python. Общее окружение
  документов печатает `hermes pm environment documents --extra documents`; порядок выбора
  интерпретатора описан в Prerequisites штатного скилла `microsoft-office`.
- **Объединённые ячейки.** В `row.cells` они повторяются; дамп дедуплицирует их по позиции,
  поэтому число колонок в выводе совпадает с видимым, а не с XML.
- **Пользовательские стили.** В отчётах заголовки часто размечены стилями `!Заг. 1/2/3`, а не
  `Heading N`: срез `--start/--end` ищет по тексту абзаца, а не по имени стиля, поэтому работает
  и там.
