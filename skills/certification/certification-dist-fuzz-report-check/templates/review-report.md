## 6. Что запросить у разработчика

1. Описательная часть: отчёт (протокол) с методикой, целями, критериями остановки и выводами.
2. Параметры сборки каждой цели: компилятор, флаги, тип инструментирования, санитайзеры, скрипт/Dockerfile, хеш бинаря.
3. Перечень датчиков срабатывания ошибок с привязкой к целям.
4. Исходные коллекции, принципы формирования, словари, правила порождения.
5. Триаж находок (`crashes/`, `hangs/`) с классификацией.
6. Подтверждение воспроизведения по каждой признанной находке.
7. `fuzzer_stats` и финальная статистика AFL там, где их нет; обоснование остановки.
8. Пояснение по покрытию: команды, бинарь, корпус, причина нулевого покрытия файлов, покрытие по базовым блокам.
9. Указание подпункта п. 5, по которому принято решение о завершении.
