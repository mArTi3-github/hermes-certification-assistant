# Определение поверхности атаки по исходным текстам

## When to Use

- Сертификационная проверка: нужно инструментально выделить участки кода, которые обрабатывают данные,
  поступающие снаружи через внешние интерфейсы, и показать, где выполняется валидация.
- Продукт передан архивом исходников (100K–10M+ строк), сборка недоступна или не учитывается.
- Нет taint-отчёта, нет доступа к стенду — результат должен получиться только из кода.
- Требуется воспроизводимый артефакт: HTML-отчёт для сдачи + JSON как источник истины.

## Scope of v0.1 (сознательно узкий)

Поддерживается: **Python + FastAPI/Starlette**. Анализ детерминированный, без сборки и без запуска.
Другие стеки — через адаптеры (см. `references/adapters.md`), контракт JSON не меняется.

Отчёт отвечает на три вопроса по каждому сетевому интерфейсу:
1. Где обработчик и какие параметры он принимает.
2. Какой код проекта достижим из него (граф вызовов, ограничение глубины).
3. Есть ли на этом пути валидация и где расположены потенциально опасные операции.

Чего отчёт **не** делает: taint-анализ (источник → сток с учётом санитайзеров), проверку рантайма,
доказательство отсутствия уязвимостей. Это фиксируется в разделе «Ограничения».

## Procedure

1. **Зафиксировать вход.** `git clone --depth 1` (или распаковать архив), записать `git rev-parse HEAD`,
   состав репозитория, исключения (`tests/`, `third_party/`, генераты). Версия и коммит попадут в отчёт.
2. **Прогнать экстрактор.**
   ```bash
   python3 scripts/surface_scan.py --root <src> --name "<продукт>" --out <outdir> [--max-depth 8]
   ```
   Выход: `<outdir>/attack-surface.html` и `<outdir>/surface.json`.
3. **Проверить полноту извлечения маршрутов независимым способом** (обязательно):
   ```bash
   grep -rhoE '@(router|app)\.(get|post|put|patch|delete|websocket)\("[^"]+"' <src> | sort | uniq -c
   ```
   Число и список путей должны совпасть с `surface.json`. Расхождение — баг адаптера, а не свойство продукта.
4. **Проверить якоря обработчиков.** Для каждой записи `handler.file:line` строка должна начинаться с `def`/`async def`.
5. **Выборочно подтвердить статусы валидации по исходнику** (минимум 5 интерфейсов, включая все с `unvalidated`
   и все с `file-upload`). Статус — эвристика, в отчёт он идёт как «признаки», а не как приговор.
6. **Проверить сгенерированные выводы** (`conclusions`): аутентификация, административные по названию интерфейсы,
   загрузка файлов, документация API. Формулировки правятся вручную, если методика требует другой лексики.
7. **Отдать HTML + JSON.** JSON — машиночитаемая модель; HTML собирается из него, не наоборот.

## Модель классификации (статусы валидации)

| Статус | Что означает | Как попадает в отчёт |
|---|---|---|
| `validated-boundary` | на границе есть схемная проверка: pydantic-модель в сигнатуре, `Field`-ограничения, `model_validate`, URL-политика | «валидация на границе» + ссылки на строки |
| `validated-in-depth` | схемная проверка есть, но только в вызываемом коде | «валидация в глубине» + цепочка |
| `partial` | только явные проверки: размер файла, `isinstance`, коды 400/413/422 | «частичная» |
| `parse-only` | только разбор (`json.loads`) и типизированные скаляры (`int`, `bool`, enum) | «только разбор» |
| `unvalidated` | признаков не найдено | «не обнаружена» — требует ручной проверки |
| `n/a` | за интерфейсом нет кода проекта (статика SPA, `/docs`, `/openapi.json`) | «не применимо» |

## Модель нарушителя

- Приоритет — **внешний нарушитель без аутентификации**; второй класс — внутренний неадмин.
- Интерфейсы, доступные **только администратору**, из поверхности исключаются, но только если ограничение
  реально есть в коде (middleware, dependency, проверка роли), а не по названию пути.
- Если аутентификации нет вообще — все интерфейсы, включая административные по назначению (`/db/*`, `/settings`),
  входят в поверхность как доступные внешнему нарушителю. В отчёте это отдельный вывод, а не молчание.
- Административность по названию пути (`admin_like`) помечается в карточке, чтобы при появлении
  аутентификации интерфейс можно было переклассифицировать.

## Требования к доказательности

- Любое утверждение — с `file:line` и текстом строки. Правило, которым найдено, тоже указывается (`kind`).
- Для каждого интерфейса печатается счётчик **неразрешённых внутренних вызовов**: это индикатор неполноты графа,
  его нельзя скрывать.
- Раздел «Ограничения» обязателен и содержит: отсутствие сборки, отсутствие taint, эвристичность графа,
  неразобранные файлы, что именно не покрыто.

## Pitfalls (проверено на реальном проекте)

- **Квалификация имён классов обязательна.** Если методы складывать как `module.method`, `self.x()` и
  `Service.method()` не разрешаются и достижимость падает до одного узла.
- **Типы локальных переменных дают основной прирост графа.** `x: Cls = ...`, `x = Cls(...)`, `x = app.state.attr`,
  `x = getattr(app.state, "attr", None)`, `x = helper()` с аннотацией возврата — всё это надо связывать с классом,
  иначе сервисный слой недостижим.
- **pydantic-модель в сигнатуре — это и есть граница валидации.** Определять по аннотации и иерархии `BaseModel`,
  а не по наличию слова `BaseModel` в теле обработчика.
- **Типизированный скаляр (`int`, `bool`, enum) — это `parse-only`, а не `unvalidated`.**
- **Не матчить имена сервисов как признак валидации**: `UrlValidationService` в аннотации — не проверка входа.
- **Эвристики проверять на собственном коде инструмента**: строка `app = FastAPI(` внутри регулярного выражения
  иначе порождает фантомные интерфейсы. Требовать реальный `from fastapi import` и импорт `StaticFiles`.
- **Выводы про «все интерфейсы без аутентификации»** сверять с документацией продукта: совпадение с разделом
  Security Notes — хороший сигнал, расхождение — повод перепроверить поиск auth-паттернов.
- **Дедуплицировать evidence** по `(file, line, kind)`: один и тот же путь достигается несколькими ветками.

## Extending

| Ситуация | Что добавить |
|---|---|
| 1M+ строк, граф нужен быстрее и глубже | `codebase-memory-mcp` как MCP-индекс (call graph, `trace_path`, Cypher) вместо AST-BFS; контракт JSON сохраняется |
| Есть сборка, нужен настоящий taint | CodeQL CLI (`codeql database create/analyze`) |
| C/C++/Java/JS без сборки | Joern CPG, см. `references/adapters.md` |
| Другой веб-стек | адаптер извлечения маршрутов + тот же JSON-контракт |
| Есть стенд | сверка статической поверхности с фактической (`ss`, OpenAPI, gRPC reflection) |

## Files

- `scripts/surface_scan.py` — экстрактор + генератор HTML (stdlib, Python 3.10+).
- `references/method.md` — контракт `surface.json`, правила статусов, шаблон разделов отчёта.
- `references/adapters.md` — как добавить язык/фреймворк, чем заменять AST-BFS на больших объёмах.
