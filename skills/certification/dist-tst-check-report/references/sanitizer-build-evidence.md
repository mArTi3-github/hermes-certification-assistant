# Комплект с компилируемой сборкой: ASan/UBSan + gcovr

Применять, когда продукт на C/C++ и в комплекте есть инструментированная сборка
(`proof/`, `evidence/`, `*/summary.json`, `MANIFEST.sha256`). Это другой набор
доказательств, чем у JS-комплектов: датчики здесь настоящие, поэтому центр
проверки смещается с «есть ли датчики» на «что датчики нашли и как это оценено».

## Что считается доказательством

| Артефакт | Команда проверки | Ожидаемое |
|---|---|---|
| Флаги всех единиц компиляции | `grep -o '\-fsanitize=[^ ]*' evidence/compile.log \| sort -u`; `evidence/configure-args.json` | `-fsanitize=address,undefined`, `-fno-omit-frame-pointer`, `-g` |
| Полнота инструментирования | `proof/compile-validation.json` | `все команды с датчиками`, стенд тоже инструментирован |
| Загрузка рантаймов | `readelf -d objs/<bin> \| grep -E 'libasan\|libubsan'` | `libasan.so.*`, `libubsan.so.*` в `DT_NEEDED` |
| Символы | `nm -u <bin> \| grep -E '__asan_\|__ubsan_'` | непустой список |
| Работоспособность датчиков | `proof/controls/{clean,asan,ubsan}` + `results.json` | чистая → код 0; asan → use-after-free; ubsan → overflow |
| Активация в прогоне | `grep -c 'AddressSanitizer Init done'` по логам | сотни процессов functional, ≥1 unit |
| Тождество исходников | `source-integrity.json` (`matches_orig`), `input-sha256.txt`, `debian/patches` | все файлы совпадают; патчей 0 |

Параметры датчиков читать из `proof/*-environment.json`: `ASAN_OPTIONS`
(`detect_leaks=1`, `halt_on_error=1`), `UBSAN_OPTIONS` (`halt_on_error=0` —
восстановление, иначе корпус не пройти; это должно быть **документировано** в
материалах, а не выведено догадкой).

## Порядок

1. Инвентаризация без распаковки: `unzip -l <zip> | tail -3`,
   `unzip -Z1 <zip> | awk -F/ '{print $1}' | sort | uniq -c`.
2. Распаковать локально (не на шаре) — комплект 50 МБ сжатого даёт ~370 МБ.
   Цикл `for z in *.zip; do unzip -oq "$z" -d ext; done`; **не** через `&` —
   terminal-инструмент отклоняет фоновые команды в одной строке.
3. Пройти таблицу выше и записать факты с путями.
4. Покрытие: `unit`/`functional`/`combined`; считать по файлам минимум и число
   ниже 25 %, а не только итог. `combined` — для усиления 4; `unit` в 3 % строк
   нормален для стенда на два десятка файлов.
5. Диагностики: сумма `occurrences` = `sanitizer_diagnostic_events`; разложить по
   детекторам (`UBSan`, `ASan`, `LSan`) и местам; проверить, есть ли оценка и
   привязка к тестам (в `leak-details.csv` колонка `test` есть, у UBSan — обычно
   нет).
6. Целостность: `shasum -a 256 -c MANIFEST.sha256 | grep -v ': OK$'` и битые
   `href` в `index.html`.

## Решения по типовым наблюдениям

| Наблюдение | Вердикт |
|---|---|
| Все команды компиляции с датчиками, символы и рантаймы на месте, контрольные программы сработали | ПОД.2-У1 «спецсборки» — **соответствует** |
| Исходники не менялись (патчей 0, 410/410 совпадает с orig), флаги только `-fsanitize`/`--coverage` | САСТ 4.2 / ЭКО 4.4 / 10 000 — **не применимо** |
| Датчики есть, но MSan/TSan не применены и не обоснованы | Перечень датчиков — **соответствует частично** |
| Диагностики собраны и сгруппированы, оценки значимости нет | ДАО.1 «г» — **соответствует частично** |
| Есть ≥50 диагностик, но нет привязки к тестам | Контрольная выборка — **не выполнена** |
| Часть файлов ниже 25 % без обоснования исключения | Усиление 4 — **не соответствует** |
| Два комплекта покрытия с разными `line_total` | Результаты — **соответствует частично**, запросить актуальный |

## Ловушки

- **`log_path` делает проверку в тестах вакуумной.** Сообщения датчиков уходят в
  файлы по PID, `error.log` чист, встроенное утверждение «no sanitizer errors»
  проходит при сотнях диагностик, а связь «тест → диагностика» теряется.
- **`debian/patches` может быть пустым — это и есть доказательство.** Не
  додумывать, что патчи применялись.
- **`ASSESSMENT.md` в манифесте без файла** — оценка находок не приложена; так и
  писать, а не «находки не описаны».
- **Версия gcovr** из README (`7.2`) против пакета (`7.2+really-1.1` = 1.1).
- **Не `cat` большие JSON** — контекст обрезается, числа теряются; агрегировать
  скриптом.
- **`objcopy --redefine-sym main=…`** — модификация объектного файла ради линковки
  стенда: фиксировать отдельно от модификаций исходников.
