# Приложение «Программные средства»: каркас и правила

Приложение обязательно в каждом заключении по DIST.TST. Ниже — готовый каркас
(копировать и заполнять) и правила, по которым его собирать.

## Правила

1. Место: последнее приложение, заголовок `##` — иначе не попадёт в оглавление
   HTML-версии. Литера — следующая после последнего приложения отчёта.
2. Таблица по компонентам — **четыре колонки**: `компонент | прогон тестов |
   съём покрытия | формат отчёта`. В ячейках только имена и версии. Команды,
   пути, флаги — в список под таблицей: пятиколоночная таблица с командами
   ломает вёрстку (перенос по 5–7 символов, горизонтальная прокрутка).
3. Один компонент — одна строка. Компоненты без покрытия не выбрасывать: строка
   с «не выполнялся» и есть доказательство пробела.
4. Версии — только из первичных артефактов (см. ниже «Откуда брать версии»).
   Нет версии — «не указана»; типовую версию из общих знаний не подставлять.
   Путь к инструменту (`/usr/bin/lcov`) — тоже факт, его указывать.
5. Список доказательств — только то, что действительно подтверждает запись:
   команда запуска, ключи покрытия, вызов инструмента, фрагмент сводки. Каждый
   пункт привязан к файлу журнала/заданию, чтобы на вопрос «где это написано?»
   был адрес.
6. Абзац «чего в материалах нет» — обязателен: отсутствующие версии (компилятор,
   рантайм, сам инструмент), конфигурации сбора, файлы, на запись которых
   указывает журнал, состав исключений при фильтрации покрытия, команды запуска.
   Этот абзац защищает от вопроса «а почему вы решили, что версия такая?».
7. Отдельная строка для сторонних зависимостей и для системных/E2E-прогонов, если
   они лежат в той же папке: они не должны выглядеть как покрытие компонента
   продукта.

## Откуда брать версии

| Что | Где | Пример |
|---|---|---|
| тест-раннер и плагины | заголовок журнала прогона | `platform linux -- Python 3.9.10, pytest-6.2.5, py-1.10.0, pluggy-1.0.0`; `plugins: django-4.4.0, cov-3.0.0, env-0.6.2` |
| инструмент покрытия (Python) | шапка HTML-отчёта | `coverage.py v6.0.2, created at 2025-06-11 19:08 +0000` |
| gcov/lcov | журнал задания покрытия | `Found gcov version: 10.2.1`; `check_present lcov` → `+ '[' -z /usr/bin/lcov ']'` |
| Go | команда задания | `go test -count=1 -race -timeout=20s -coverprofile=cover.out ./...`; `go tool cover -func=cover.out \| tail -n1` |
| C++ сборка | журнал meson/ctest | `meson test -t 40 -C …`, `1/79 … OK`, `Ok: 79 / Fail: 0` |
| frontend | package.json-скрипты в журнале | `npm run typecheck` → `tsc --build --noEmit`; `format:check` → prettier; `lint:check`; `knip` |

## Каркас

```markdown
## Приложение Г. Программные средства, которыми выполнялись тестирование и съём покрытия

| Компонент | Прогон тестов | Съём покрытия | Формат отчёта |
|---|---|---|---|
| `<компонент>` | <раннер + версия>, плагины <…> | <инструмент + версия> | <HTML / XML / CSV / lcov> |
| `<компонент без покрытия>` | <раннер + версия> | не выполнялся | — |
| `<сторонняя зависимость>` | <раннер> | <инструмент> | <формат> |
| системные/E2E-прогоны | <инструмент>, версия не указана | не относится к покрытию | HTML |

Перечень программ:

| Программа | Версия | Назначение | Компонент |
|---|---|---|---|
| pytest | 6.2.5 | запуск тестов | `a` |
| coverage.py | 6.0.2 | измерение покрытия, HTML/XML | `a` |
| CTest (CMake) | не указана | запуск тестов C++ | `b` |

Команды и фрагменты (доказательства):

- `<компонент>`, задание `<название (#номер)>`: `<команда запуска>`; `<строка сводки с числом>`.
- `<компонент>`: `<ключи покрытия>`; `<где видно версию инструмента>`.

**Чего в материалах нет:** версий <…>, конфигурации сбора покрытия, файла
`<coverage.xml>`, на запись которого указывает журнал, состава исключений,
команд запуска тестов.
```

## Проверка перед сдачей

- Приложение есть, стоит последним, заголовок уровня `##`, литера не дублирует
  предыдущее приложение.
- В таблице по компонентам нет длинных команд; все команды — в списке ниже.
- У каждого компонента отчёта есть строка в приложении (включая те, где покрытие
  не снималось).
- Ни одной версии «по памяти»: каждая либо с адресом артефакта, либо «не указана».
- Есть абзац «чего в материалах нет».
- В HTML-версии: приложение видно в оглавлении, таблица не даёт горизонтальной
  прокрутки.
