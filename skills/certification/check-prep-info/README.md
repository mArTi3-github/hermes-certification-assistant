# check-prep-info — проверка PREP.INFO

Скилл проверяет PREP.INFO — документ подготовки информации об изделии, который разработчик
передаёт на сертификацию. Проверяется сам документ и его сходимость с
эксплуатационной документацией (ЭД) того же продукта и той же версии; тестирование,
сборка и оценка кода в задачу не входят.

## Что делает

Проходит документ сверху вниз и по каждому пункту выдаёт вердикт и замечания:

| Пункт | Что проверяется |
|---|---|
| 2.1 | назначение и функциональные возможности изделия |
| 2.2 | аппаратные и программные требования, среда функционирования |
| 2.3 | состав поставки (дистрибутив, установочные пакеты, архивы) |
| 2.4 | функции безопасности (ФБ) изделия |
| 3 | архитектура: схема крупных компонентов и внешних субъектов |
| 4 | внешние интерфейсы |
| 5 | подсистемы: реализующие и поддерживающие ФБ, механизм невозможности влияния |
| 6.1 | модули — ФБ и поверхность атаки |
| 6.2 | модули — описание интерфейсов и возвращаемых значений |
| 6.4 | представление реализации: языки, интерпретаторы и среды с точными версиями |
| 6.5 | инструменты разработки и сверка версий с 6.4 |

**Пункт 6.3 «Заимствованные компоненты» из проверки исключён**: раздел устарел и выводится
из PREP.INFO. Замечаний по нему скилл не пишет; если раздел в документе ещё есть, в отчёте
остаётся одна строка о том, что он подлежит удалению.

Вердикт ставится по каждому пункту из словаря: «Соответствует», «Соответствует частично»
(принято с замечаниями), «Не соответствует» (не принято). Мелкие замечания — опечатки,
вёрстка, стиль — фиксируются с меткой «мелкое» и на вердикт не влияют. Рекомендации к
заполнению идут отдельным блоком после вывода, с готовой формулировкой для вставки в
PREP.INFO, и приёмку не блокируют.

На выходе два файла: `<продукт>-prep-info-review-report.md` и автономный `.html` (открывается
без интернета, с оглавлением и подсветкой вердиктов). Оба кладутся в ту же папку, откуда взяты
материалы.

## Как вызвать

Фразой в чате — этого достаточно, скилл загрузится сам:

```
проверь PREP.INFO
```

Явно, если нужно назвать именно этот скилл:

```
вызови скилл check-prep-info
```

Полное имя с категорией — `certification/check-prep-info`.

## Что нужно на входе

1. **PREP.INFO (PDF)** — обязателен. Версия и SHA-256 фиксируются в шапке отчёта, чтобы
   заключение относилось именно к проверенной редакции.
2. **ЭД той же версии** — руководства администратора, пользователя и разработчика.
   Минимум для сверки — администратора и пользователя; без руководства разработчика нечем
   сверить коды ответов API и поведение интерфейсов (пп. 4, 6.2).

## Если руководств нет

Скилл не начинает проверку молча. Он говорит прямо, что сверка с ЭД невозможна, перечисляет,
каких документов не хватает и какие пункты из-за этого останутся без сверки, и предлагает выбор:

1. дождаться руководств (минимум администратора и пользователя той же версии);
2. проверить только внутреннюю согласованность — 2.1–2.4 между собой, 3 ↔ 5 ↔ 6.1 ↔ 6.2 ↔
   6.4 ↔ 6.5, схема ↔ порты ↔ п. 2.2 — и в шапке отчёта написать «ЭД не представлены, сверка
   не выполнялась; отчёт неполный».

Если ЭД есть, но другой версии, скилл скажет об этом и укажет в шапке, с какой версией
сверялся. Выдавать неполную проверку за полную он не будет.
