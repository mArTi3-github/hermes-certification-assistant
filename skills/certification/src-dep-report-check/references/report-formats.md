# Формы входных отчётов

## Колонки: синонимы

Отчёты одного происхождения называют одни и те же сущности по-разному. Шапка определяется
совпадением имён, а не позицией колонки:

| Поле | Имена в отчётах |
|---|---|
| продукт, название | `name`, `ancestor_component_name`, `product` |
| продукт, версия | `version`, `ancestor_component_version` |
| purl продукта | `purl`, `ancestor_component_purl` |
| заимствованный компонент | `component`, `component_purl` — purl вида `pkg:type/имя@версия` |
| id уязвимости | `id`, `vuln_id`, `cve` |
| уровень опасности | `severity`, `уровень опасности` |
| статус | `status`, `статус` |
| обоснование | `detail`, `обоснование`, «разметка» |

Если в отчёте одновременно `purl` и `component`, то `purl` — продукт, а `component` — уязвимый
заимствованный компонент. Перепутать их значит проверить не тот объект.

## Раскладка листов

- **Шапка не в первой строке.** Над ней бывает служебная строка (`Column1…Column8`, имя таблицы
  Excel); шапку искать в первых десяти строках по числу совпавших имён колонок.
- **Служебный лист с сырым дампом.** Второй лист часто содержит исходный CSV целиком в одной
  колонке (по строке на ячейку). Он не табличный: разбирать его как отчёт нельзя, а отсутствие
  шапки на таком листе — не ошибка входа.
- **Файл неразрешённых уязвимостей.** Отдельный файл вида
  `component, version, cve, severity, reason` — уязвимости, для которых не нашлось места в SBOM.
  Пустой файл (одна шапка) — нормальный результат, а не сбой.

## Кодировка и разделители (csv)

- BOM в начале (`utf-8-sig`), CRLF, разделитель `;`, `,` или таб — определять по первой строке,
  а не по расширению.
- Названия содержат `@`, `/`, `.`, а purl — `%40`, `%2B`, `?arch=…&distro=…`. Перед сравнением
  версий из purl снимать URL-кодирование, иначе `17.9-0%2Bdeb13u1` не сойдётся с
  `17.9-0+deb13u1` и появится ложное расхождение.
- Обоснование может содержать `;` и переводы строк внутри кавычек — читать csv-парсером, не
  `split(';')`.

## xlsx без внешних библиотек

`scripts/src_dep_probe.py` читает xlsx как zip-архив: `xl/workbook.xml` (имена и порядок листов),
`xl/_rels/workbook.xml.rels` (`r:id` → файл листа), `xl/sharedStrings.xml` (общий словарь строк)
и `xl/worksheets/sheetN.xml` (ячейки). Типы значений: `t="s"` — индекс в общем словаре,
`t="inlineStr"` — текст внутри ячейки, иначе — число в `<v>`. Пустая ячейка может отсутствовать
в XML: выравнивать колонки по атрибуту `r` ячейки, а не по порядку элементов.
