# Инструменты окружения: проверка до работы, установка по согласию

Кампания упирается не в методику, а в отсутствующий `docker` на машине исполнителя.
У коллег набор инструментов разный, поэтому наличие проверяется **до** первой команды,
а не в момент, когда сборка уже должна была пройти.

## Что нужно кампании

| Инструмент | Зачем | Обязательность |
|---|---|---|
| `docker` (или `podman`) | сборка образа и прогоны с `--network none` | обязательно |
| `git` | клон компонента, `cncf-fuzzing`, `oss-fuzz` на фиксированных коммитах | обязательно |
| `python3` (3.9+) | скрипты статуса, индекса, сверки чисел | обязательно |
| `sha256sum`, `tar`, `gzip` | хеши, комплект одним архивом | обязательно |
| `jq` | разбор `status.json`, `fuzzer_stats` | очень желательно |
| `curl` | проверка доступности хоста и эндпоинтов | очень желательно |
| `ssh`, `rsync` | кампания на отдельной ВМ | только для удалённого варианта |
| `tmux` | длинный прогон, переживающий закрытие чата | только для локального варианта |
| JDK + Maven | сборка вне образа | не требуется, если всё собирается в контейнере |

Проверка одной командой:

```bash
for t in docker git python3 jq curl sha256sum tar gzip ssh rsync tmux; do
  printf '%-10s %s\n' "$t" "$(command -v "$t" || echo '— нет')"
done
docker version --format '{{.Server.Version}}' 2>/dev/null || echo "docker: демон недоступен"
```

Последняя строка важнее первой: `docker` в PATH может быть, а демона и прав на сокет —
нет (`permission denied while trying to connect to the Docker daemon socket`).

## Если чего-то нет

1. **Назвать список явно** — что именно отсутствует и что из-за этого нельзя сделать.
   «Не хватает docker и ssh» — ответ; «проверка невозможна» — нет.
2. **Предложить установку** с командой под дистрибутив исполнителя и спросить разрешение:
   установка идёт от `sudo` и меняет чужую машину, поэтому молча не выполняется.
   ```bash
   # Debian/Ubuntu
   sudo apt-get update && sudo apt-get install -y docker.io jq rsync openssh-client
   # RHEL/Fedora
   sudo dnf install -y docker jq rsync openssh-clients
   # macOS
   brew install jq rsync
   ```
   Docker Desktop / Engine на macOS и Windows ставится мастером установки, а не строкой —
   это проговаривается отдельно.
3. **Предложить обход, если ставить нельзя**: `podman` вместо docker (флаги совместимы,
   `--network none` работает), контейнер с инструментами, отдельная ВМ, где набор уже есть.
   Обход называется вместе с ценой: podman меняет имена образов в логах, ВМ требует доступа
   по SSH и переноса материалов.
4. **Зафиксировать ограничение**, если обход не годится: в брифе и в отчёте пишется, какая
   часть требования закрыта не полностью и почему (например, «п. 5«б» не снимался: JaCoCo
   требует прогона, docker на машине исполнителя отсутствует»).

## Что записывается в материалы

`evidence/build/tools-versions.txt` — вывод `command -v` и версий (`docker`, `python3`,
фаззер, JDK, Maven, JaCoCo, Jazzer) с машины, где шёл прогон. Файл входит в `SHA256SUMS`:
он объясняет проверяющему, чем именно получены артефакты, и отличает «не воспроизвелось»
от «воспроизводилось другим инструментом».

## Удалённая ВМ

Набор проверяется **на обеих** машинах: локальная нужна для `ssh`/`rsync` и сборки архива,
удалённая — для docker и прогонов.

```bash
ssh <пользователь>@<вм> 'for t in docker git python3 jq; do printf "%-8s %s\n" "$t" "$(command -v "$t" || echo нет)"; done'
```

`docker` без прав у пользователя (`sudo` нужен на каждый вызов) — отдельная проблема:
в этом случае прогоны идут через `sudo docker`, а очередь и сторож запускаются с тем же
префиксом, иначе ночью контейнеры не стартуют. Проверять до кампании, а не после.

## Правило

Проверка инструментов — часть брифа, а не аварийный сценарий: список, установка по согласию,
зафиксированные версии. Отсутствующий инструмент никогда не «компенсируется» текстом отчёта:
либо требование закрыто прогоном, либо в отчёте написано, что и почему не снималось.
