# Дополнения к штатному скиллу `hermes-agent`

Базовый скилл `hermes-agent` — **штатный, его нельзя править**: любая правка каталога
отвязывает его от апстрима (`~ hermes-agent (user-modified, skipping)`), и обновления
Hermes перестают приезжать. Всё, чего нет в стоковой версии, живёт здесь.

## Когда применять

Когда вопрос про сам Hermes выходит за рамки стокового `hermes-agent`: размер контекста и
компакция, доступ к бэкенду с другой машины, раздача скиллов команде, и где в этой рабочей
среде физически лежат файлы, которые человек называет «на рабочем столе».

## Правила

1. Сначала загрузить стоковый `hermes-agent` — он описывает установленную версию и обновляется
   вместе с Hermes. Эти заметки его дополняют, а не заменяют.
2. Расхождение с апстримом проверять так: `hermes skills list-modified`,
   `hermes skills diff hermes-agent`. Если стоковая версия начала противоречить фактам на
   стенде — обновить Hermes (`hermes update`), а не править скилл.
3. Появилось что-то, чего нет в стоке → новый файл в `references/` **здесь**, а не в
   `hermes-agent`.
4. Долгоживучесть скиллов задаётся отсутствием маркера курирования, а не пином: скилл, приехавший
   из репозитория, не имеет `created_by: agent`, в `curated_report()` не входит, и куратор его не
   видит — не запускать `hermes curator adopt` (ни по одному, ни `--all-unmanaged`), иначе скилл
   начнёт стареть по общим срокам, а обратной команды нет. Пин — рычаг для скилла, созданного
   фоновой ревизией; неуправляемому он не нужен и втягивает его в список кандидатов. Подробности —
   `references/skill-lifecycle-and-curator.md`. Правило, которое должно пережить работу куратора,
   пишется в `SOUL.md` профиля, а не в скилл.
5. Пункт в настройках Desktop не доказывает, какой ключ он правит: сверять по
   `hermes config get` и исходникам клиента (`apps/desktop/src/app/settings/constants.ts` — состав
   вкладок). «Тайм-аут подтверждения» в разделе «Безопасность» — это `approvals.timeout`
   (подтверждения команд), а не таймаут вопросов; `0` там — мгновенное истечение, а не «без
   таймаута». Разбор двух ключей — `references/clarify-and-approval-timeouts.md`.
