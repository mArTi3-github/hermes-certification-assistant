# Файлы от пользователя: рабочий стол, корзина, общие папки

Что делать, когда человек говорит «я положил файл на рабочий стол» или «в папке <имя>», а в
гостевой системе этого нет. Рабочая среда — гостевая ВМ: «рабочий стол» из рассказа человека
может быть рабочим столом **хоста**, и в гость он попадает только через общую папку.

## Порядок проверки

1. `ls -la ~/Desktop` — каталог существует и часто пуст: файлы приходят не туда, а следы
   перетаскивания остаются в корзине (шаг 4).
2. `vmware-hgfsclient` — печатает имена общих папок хоста, даже когда они не смонтированы. Пустой
   `/mnt/hgfs` — это «не смонтировано», а не «папки нет».
3. Монтирование: `sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other`; содержимое появляется в
   `/mnt/hgfs/<шара>`. Постоянно — строка в `/etc/fstab`:
   `.host:/ /mnt/hgfs fuse.vmhgfs-fuse allow_other,defaults 0 0` (по умолчанию её нет, поэтому
   после перезагрузки шаринг снова пропадает и вопрос повторяется).
4. Исчезнувшие с рабочего стола файлы — в корзине: `~/.local/share/Trash/info/*.trashinfo` хранит
   исходный путь (percent-encoded) и время удаления, `~/.local/share/Trash/files/` — само
   содержимое. Это единственное место, где видно, что лежало на рабочем столе.
5. Откуда файл открывали: `~/.local/share/recently-used.xbel` (href, свежие сверху) и закладки
   файлового менеджера `~/.config/gtk-3.0/bookmarks`.

## Ловушки

- **Отвечать «файла нет», не вызвав `vmware-hgfsclient`.** Пустой `/mnt/hgfs` без записи в
  `/etc/fstab` — обычное состояние этой ВМ; поиск по всему дереву (`find / -iname '*<имя>*'`)
  в таком состоянии честно ничего не находит, и это ответ про монтирование, а не про файл.
- **Считать хост этой же машиной.** Если человек говорит «у меня на рабочем столе», файл может
  физически лежать на хосте: называть надо путь **в госте** (`/mnt/hgfs/<шара>`) и говорить, что
  это общая папка.
- **Перебирать варианты вместо ответа.** Ответ — путь, что внутри (файлы, размер, при возможности
  краткая структура), и одна строка про постоянное монтирование.
