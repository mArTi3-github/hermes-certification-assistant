# Таймауты карточек: вопросы и подтверждения

Два независимых ключа. Оба читаются живым кэшем конфига — перезапуск не нужен.

| | Карточки вопросов (`clarify`) | Карточки подтверждения команд |
|---|---|---|
| Ключ | `agent.clarify_timeout` | `approvals.timeout` |
| По умолчанию | 90 с | 300 с (5 минут) |
| Значение `0` | ждать без ограничения | ноль секунд: карточка истекает мгновенно, команда блокируется как несогласованная |
| Где в Desktop | не выведен в настройки | «Настройки → Безопасность → Подтверждение → Тайм-аут подтверждения» |
| Ограничения значения | `<= 0` передаётся в ожидание как есть | есть только верхняя граница (≈ год), нуля-исключения нет |

Ключи не взаимозаменяемы: правка пункта «Тайм-аут подтверждения» в Desktop на таймаут вопросов
не влияет вообще, и наоборот.

## Команды

```bash
hermes config get agent.clarify_timeout      # 0 — ждать без ограничения
hermes config get approvals.timeout          # 0 здесь = мгновенное истечение подтверждений
hermes config set agent.clarify_timeout 0
hermes config set approvals.timeout 300      # дефолт; больше — если человек отвечает не сразу
```

Отдельный рычаг — `approvals.mode` (`manual` / `smart` / `off`): `off` снимает подтверждение
опасных команд целиком, а не растягивает окно. На рабочей машине `manual` + разумный таймаут
безопаснее, чем `off`.

## Распознавание по симптому

- «Карточка с вопросом вернулась `timed_out`» → смотреть `agent.clarify_timeout`, затем отправить
  одну пробную карточку с безобидным вопросом. Только `undelivered` означает, что поверхность
  карточек не умеет; `timed_out` — почти всегда значение настройки.
- «Команда не выполнилась, в ответе `No answer within 0 seconds` или `The user has NOT consented`»
  → это `approvals.timeout = 0`, а не отказ человека: подтверждение истекло раньше, чем дошло до
  экрана.
- «Выключил таймаут в настройках, а карточки всё равно моментально закрываются» → правился
  `approvals.timeout`; для вопросов нужен `agent.clarify_timeout`.

## Где проверить, какой ключ у пункта UI

Состав вкладок задаётся в исходниках клиента (`apps/desktop/src/app/settings/constants.ts`,
вкладка `safety`): там перечислены `approvals.mode`, `approvals.timeout`,
`approvals.mcp_reload_confirm`, `command_allowlist` и другие. Ключа `agent.clarify_timeout` в этом
списке нет — поэтому его заводят только через `hermes config set`, а не через панель.
