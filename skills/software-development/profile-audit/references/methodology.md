# Откуда взят метод: сравнение трёх скиллов

Сравнение сделано по исходникам, а не по описаниям. Лицензии проверены там, где репозиторий их
публикует; текст чужих скиллов не копировался — перенесены принципы, формулировки написаны заново.

## Grill-me (mattpocock/skills)

- Файл `skills/productivity/grill-me/SKILL.md` — обёртка, которая вызывает примитив `grilling`.
  Суть лежит в `skills/productivity/grilling/SKILL.md`.
- Принципы: интервью идёт «фронтом» — сначала все вопросы, ответы на которые не зависят от
  других; факты собирает агент, решения принимает человек; вопрос без вариантов лучше вопроса
  с навязанным выбором; один вопрос за раз, если вопросы связаны.
- Сильная сторона: дисциплина «не спрашивай то, что можешь выяснить сам», отсечение
  необязательных уточнений, явное разделение «факт / решение».
- Слабая сторона для аудита: предполагает, что предмет уже известен и его надо только
  допросить; нет шага «собрать улики» и нет классификации расхождений.
- Взято: правило «факты — работа агента», один вопрос за раз, запрет на повторные вопросы.
- Лицензия репозитория — MIT (файл `LICENSE` в корне).

## Brainstorming (obra/superpowers)

- Принципы: сначала разведка контекста, потом вопросы; «play it back» — пересказать понимание
  своими словами и получить подтверждение; предложить 2–3 подхода с плюсами и минусами;
  зафиксировать решение отдельным артефактом; не переходить к реализации без согласия.
- Сильная сторона: цикл «разведка → понимание → варианты → согласие → артефакт» точно
  соответствует задаче аудита, где артефакт — согласованная версия профиля.
- Слабая сторона: оптимизирован под проектирование нового, а не под разбор уже написанного;
  нет понятия «противоречие» и «достоверность источника».
- Взято: разведка до вопросов, пересказ понимания перед правкой, 2–3 варианта вместо меню,
  артефакт-отчёт, согласие до изменения.
- Лицензия — MIT (`LICENSE` в корне).

## Hyperplan (code-yeongyu/oh-my-openagent)

- Принципы: независимая проверка гипотез несколькими «ролями», критика выводов, поиск логических
  противоречий, проверка с разных точек зрения.
- Сильная сторона: требование попытаться опровергнуть собственный вывод до того, как его
  показывать.
- Слабая сторона: многоагентная архитектура завязана на внешние инструменты и на порядок
  «сначала план, потом исполнение»; в Hermes это лишняя машинерия, а для аудита — лишний шум.
- Лицензия: файл лицензии в ветке `dev` не публикуется по ожидаемому пути; права неясны, поэтому
  текст не переносился — только идея последовательной самопроверки.
- Взято: шаг «попытайся опровергнуть находку» (шаг 3 процедуры). Отброшено: роли, оркестрация,
  отдельный формат плана.

## Что получилось в итоге

Собственный каркас: детерминированный сканер улик → опровержение своих гипотез → интервью по
одному вопросу → предложение правок с явным согласием → отчёт и журнал для инкрементальных
прогонов. Ни один из трёх источников не покрывал шаг «собрать проверяемые улики из файлов»,
поэтому он реализован как скрипт, а не как абзац инструкции.
